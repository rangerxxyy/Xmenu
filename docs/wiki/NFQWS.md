Открывается пунктом **12**. Стратегии и синхронизация используют найденный активный конфиг с приоритетом NFQWS2. Для IPSet, rkn.list и обхода DNS при установленных v1/v2 доступен выбор версии или обеих сразу.

```text
1.  Выбрать и применить стратегию nfqws
2.  Установить все blobs nfqws2
3.  Скачать/проверить blobs и lists активной стратегии
4.  Скачать rkn.list (nfqws / nfqws2)
5.  Обход блокировки DoT/DoH
6.  Настройки текущих DNS-серверов
7.  Обновить Ipset Lists
8.  Смена текущих fake:blob
9.  Discord: включить/выключить фикс
10. Обновление hosts
0.  Назад
```

### 1. Выбрать и применить стратегию

Показывает каталог конфигураций для выбранной версии. Основной список NFQWS2 сохраняет **40 вариантов**. Пункт **99 — Дополнительные конфигурации** выделен ярким бирюзовым и открывает отдельный список из **17 файлов** без повторов основного каталога. Совпадения по названию или SHA-256 скрываются автоматически.

- Активная стратегия определяется сравнением с действующим конфигом.
- Манифест с контрольными суммами кэшируется на час; конфиги скачиваются по выбору.
- Для дополнительных стратегий манифест и конфиг берутся из одной ревизии репозитория.
- Перед заменой сохраняется резервная копия, проверяется SHA-256 и синтаксис конфигурации.
- После применения перезапускается соответствующий сервис; ошибка перезапуска выводится отдельно.

Проверенный локальный кэш используется при недоступности загрузки. Работоспособность конкретной стратегии зависит от провайдера, версии NFQWS и маршрута трафика.

В конфигурациях удалены комментарии и поясняющий текст, исправлены кавычки, определения blobs, порядок переменных MODE, одиночные позиции разделения и пустые/разорванные ветки circular. Убраны неподдерживаемые параметры и SYN-правила, которые не могли выполняться внутри ограниченного TLS-профиля. Файлы проверены установленным движком через dry-run и инициализацию Lua без перехвата трафика. Это подтверждает корректность параметров и загрузки, но результат обхода проверяется в своей сети.

<details>
<summary><b>Пошагово: выбрать стратегию и проверить результат</b></summary>

1. Установи NFQWS2 через пункт **4**, если пакет ещё отсутствует.
2. Открой **12 → 1**. При доступном источнике загрузится каталог; при наличии проверенного кэша он может быть использован повторно.
3. Выбери конфигурацию по её номеру.
4. Xmenu проверит SHA-256 загруженного файла, подготовит конфиг и ресурсы, создаст резервную копию и заменит действующий файл.
5. Дождись сообщения о перезапуске службы. При его ошибке проверь конфиг и вывод `/opt/etc/init.d/S51nfqws2 status`.
6. Проверь нужные сайты и приложения из своей сети. Успешная проверка файла означает его целостность и корректный shell-синтаксис; результат обхода зависит от условий подключения.

```text
Главное меню
└─ 11. Управление nfqws2
   ├─ 1. Выбрать и применить стратегию nfqws
   ├─ 3. Скачать/проверить blobs и lists активной стратегии
   └─ 9. Discord: включить/выключить фикс
```

</details>

<details>
<summary><b>Что сохраняется при замене стратегии</b></summary>

| Данные | Поведение Xmenu |
| --- | --- |
| Предыдущий конфиг | Сохраняется в резервной копии до замены |
| `ISP_INTERFACE` | Переносится из действующего конфига буквально, включая список интерфейсов |
| Подключённый `rkn.list` | Его привязка сохраняется при подготовке новой стратегии |
| Ручные изменения остальных аргументов | Новая стратегия задаёт свои значения; прежние остаются в копии конфига |
| Активный вариант | Определяется сравнением конфигурации с проверенным кэшем |

Если у тебя собственные параметры политик, портов или IPv6, сравни новый конфиг с резервной копией перед дальнейшими ручными изменениями. Xmenu не обещает автоматически объединить все пользовательские аргументы с другой стратегией.

</details>

<details>
<summary><b>Как выбирается v1 или v2</b></summary>

| Операция | Выбор версии |
| --- | --- |
| Стратегия и синхронизация активных ресурсов | При наличии двух конфигов приоритет имеет NFQWS2; если он отсутствует, используется NFQWS v1 |
| Смена fake:blob | При двух конфигурациях открывается выбор v1 / v2 |
| rkn.list, IPSet, обход блокировки DoT/DoH | При двух установленных версиях можно выбрать одну либо обе |
| Discord Fix | Работает с NFQWS2 |
| Настройка DNS и hosts | Изменяет настройки самой прошивки Keenetic через ndmc |

Основной конфиг v1 — `/opt/etc/nfqws/nfqws.conf`; v2 — `/opt/etc/nfqws2/nfqws2.conf`. Доступность выбора определяется найденными конфигами или установленными пакетами в зависимости от операции.

</details>

<details>
<summary><b>Чем отличаются blobs, lists, IPSet и rkn.list</b></summary>

| Термин | Что хранится | Для чего нужен |
| --- | --- | --- |
| **Стратегия** | Shell-конфигурация `.conf` | Задаёт фильтры трафика, аргументы обработки, порты и пути к ресурсам |
| **Blob** | Бинарный файл `.bin` | Содержит данные fake-пакета или другого ресурса стратегии |
| **Hostlist / lists** | Текстовый список доменов | Ограничивает применение стратегии указанными именами |
| **IPSet list** | IP-адреса и сети CIDR | Выбирает трафик по адресам назначения |
| **rkn.list** | Отдельный доменный список | Подключается к конфигу как дополнительный hostlist |
| **hosts** | Пары `IP DOMAIN` | Создаёт статические DNS-привязки в прошивке роутера |

Пункт **12 → 2** загружает все доступные blobs NFQWS2. Пункт **12 → 3** работает с зависимостями активного конфига. **12 → 7** заменяет конкретный IPSet-список, а **12 → 10** управляет статическими DNS-привязками.

</details>


### 2. Установить все blobs NFQWS2

Скачивает каталог `.bin`-ресурсов в `/opt/etc/nfqws2/blobs`. Проверяет уже имеющиеся файлы и сверяет загруженные с контрольными суммами. В конце сообщает число обработанных файлов и ошибок.

**Когда использовать:** после первой установки NFQWS2 или перед проверкой нескольких стратегий, использующих разные fake-пакеты.

### 3. Проверить ресурсы активной стратегии

Разбирает пути к blobs и lists в действующем конфиге, проверяет наличие нужных файлов и загружает отсутствующие ресурсы. Обрабатывает зависимости текущего конфига, а не весь доступный каталог.

Если действующий конфиг совпадает с ранее выбранной и сохранённой в кэше стратегией, синхронизация также может обновить этот вариант из свежего каталога. При ручных изменениях, из-за которых конфиг перестал совпадать с кэшем, автоматическая замена стратегии пропускается; проверяются её ресурсы.

### 4. Скачать rkn.list

Обновляет доменный список для выбранного NFQWS, при необходимости добавляет ссылку на него в конфигурацию. Изменения сохраняются с резервной копией; сервис перезапускается, когда список или конфиг действительно изменились.

### 5. Обход блокировки DoT/DoH

Добавляет стратегию доступа к публичным защищённым DNS в `NFQWS_ARGS_CUSTOM`: для v1 используется классический desync, для v2 — Lua-стратегия. Проверяет наличие порта `853` в `TCP_PORTS` и `UDP_PORTS`, сохраняет конфиг и перезапускает выбранную службу.

Стратегия загружается отдельным файлом; при недоступности источника используется встроенный вариант. Ответ `n` отменяет действие **до загрузки, резервного копирования и записи**.

**Эта операция помогает получить доступ к DNS-сервисам.** Настройка самих DNS-серверов находится в следующем пункте.

### 6. Настройки текущих DNS-серверов

Открывает встроенное управление DNS Keenetic через `ndmc`. Подробное описание — [ниже](Full-guide.md#настройки-dns-серверов).

### 7. Обновить IPSet Lists

Предлагает большой IP/CIDR-список Flowseal или стандартный список выбранного пакета. Можно обработать v1, v2 или обе версии.

| Версия | Файл |
| --- | --- |
| NFQWS v1 | `/opt/etc/nfqws/ipset.list` |
| NFQWS2 | `/opt/etc/nfqws2/lists/ipset.list` |

Перед записью удаляются комментарии и пустые строки, проверяется непустой результат и сохраняется резервная копия. После обновления перезапускается соответствующая служба. Большой список увеличивает объём обрабатываемых адресов и потребление ресурсов роутера.

### 8. Смена текущих fake:blob

Находит именованные `fake:blob=NAME` по секциям конфига и показывает файл, на который указывает `--blob=NAME:...`. Hex-значения пропускаются, повторяющиеся имена объединяются.

После выбора предлагает локальные `.bin`, файлы из манифеста или резервного каталога. Скачивает выбранный ресурс, переназначает путь `--blob`, проверяет shell-синтаксис и сохраняет конфигурацию с бэкапом. Перезапуск службы выполняется по подтверждению.

### 9. Discord Fix

Направляет UDP-пакеты голосовой сессии на портах **19294–19344** и **50000–50100** в NFQWS2 на протяжении звонка. При наличии цели `PPE` исключает эти потоки из ускорения прошивки. Учитывает интерфейсы, номер очереди и политики выбранной конфигурации NFQWS2, включая значения из `.run`.

```text
1. Статус / диагностика
2. Включить фикс
3. Выключить фикс
4. XKeen: исключить порты Discord   [если установлен XKeen]
0. Назад
```

При включении создаются собственные цепочки firewall, init-скрипт и хук восстановления правил. Выключение снимает правила Xmenu и удаляет файлы включения фикса. Пункт XKeen добавляет порты в `port_exclude.lst` и предлагает перезапуск работающего XKeen.

Фикс обеспечивает обработку сессии; подходящая стратегия Discord должна быть в конфигурации NFQWS2. После включения переподключись к голосовому каналу.

### 10. Обновление hosts

Загружает список статических DNS-привязок, разбитый на секции. Можно выбрать несколько секций через запятую, все записи, удалить домены из этого списка или посмотреть текущие привязки.

```text
1…N. Секции hosts-файла
  a. Все секции
 88. Удалить домены из этого hosts-файла
 99. Показать текущие записи
  0. Назад
```

Записи применяются командой `ip host DOMAIN IP`, удаляются через `no ip host DOMAIN`. Поддерживается IPv4; некорректные адреса и домены пропускаются, для каждого домена сохраняется один IP. Перед изменением создаётся копия текущих `ip host`, затем сохраняется конфигурация Keenetic. При выборе более 64 доменов показывается предупреждение о лимите роутера.
